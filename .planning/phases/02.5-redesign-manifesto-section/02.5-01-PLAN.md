<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shopify theme editor -> Liquid schema | Merchant-controlled input (image_picker selections, tagline text) entered via Shopify Admin, not end-user/visitor input |
| Liquid render -> data-* attribute -> React prop | Server-rendered string flows into the DOM and then into React via getAttribute; values originate from Shopify's own CDN (image_url) and Liquid's `escape` filter (text) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02.5-01 | Tampering/Injection | data-manifesto-tagline-* attributes | mitigate | Already uses Liquid's `escape` filter (matches existing `data-about-heading` pattern) — prevents HTML/attribute breakout if a merchant pastes markup into the tagline text setting |
| T-02.5-02 | Information Disclosure | data-manifesto-image-* attributes | accept | Image URLs resolve through Shopify's `image_url` filter to Shopify's own CDN — no user-controlled URL strings are ever rendered raw; this is the same trust level as every other image_picker render in the theme (page-about.liquid) |
| T-02.5-03 | Tampering | image_picker settings with no `default` | accept | Intentional per D-04 blocker — omitting a default is a content-completeness concern (merchant must assign images via customizer), not a security risk; empty data-* attribute values are handled as falsy/empty-string in Plan 02's React consumption |
</threat_model>
