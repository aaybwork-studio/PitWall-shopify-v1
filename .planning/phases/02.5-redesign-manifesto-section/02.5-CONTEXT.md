<decisions>
## Implementation Decisions

### Image Assets & Sourcing
- **D-01 (Reference vs. assets):** The attached composite image ("Image 1" in the discussion) is a layout/style reference ONLY — not a literal asset. The 3 separately-attached high-resolution photos are the actual source images.
- **D-02 (Panel-to-image mapping):**
  - Panel 1 ("THE RACE."): motion-blur F1 car, front 3/4 angle, racing on track
  - Panel 2 ("THE MOMENT."): driver holding trophy aloft on podium, crowd with cameras in background
  - Panel 3 ("YOURS."): black F1 car, studio shot, dark background, side/3-4 angle
- **D-03 (Tagline copy):** Use the exact reference copy verbatim — "THE RACE.", "THE MOMENT.", "YOURS." (with periods).
- **D-04 (Asset delivery mechanism):** Add 3 `image_picker` settings to the Manifesto/hero-canvas section schema, with these 3 images set as the schema defaults — matches the editable-via-customizer pattern used by every other section (About, hero stats, founding story, etc.). Do NOT hardcode static asset filenames.
- **D-05 (Taglines are live text, not baked into images):** Taglines render as actual DOM text with `mix-blend-mode: difference` overlaid on each image — NOT pixels baked into the photo. This keeps them sharp, animatable, and editable via schema text settings (matching the existing `about_heading`/`cta_label` pattern).

### Reveal Animation Mechanic
- **D-06 (Animation type):** Scale-up-from-center: each panel animates from ~90% scale + opacity 0 to 100% scale + opacity 1 (not a slide or clip-path wipe).
- **D-07 (Stagger):** Staggered left-to-right — Panel 1 starts first, Panel 2 follows ~120-150ms later, Panel 3 follows ~120-150ms after that. Cascading, not simultaneous.
- **D-08 (Trigger):** The reveal fires when Manifesto becomes the active scroll-snap section — reuse the same motion-value-tied-to-scroll-position mechanism Group 3's intro label/story panel already use (`useTransform`/`useMotionValue` driven off scroll progress), NOT a generic IntersectionObserver-on-mount-once trigger like the product grid's `.reveal-active` class. This section is scroll-snap-driven like the rest of the homepage, so the reveal should feel tied to "arriving" at the section, not just "having scrolled past a threshold."

### Layout & Responsive Behavior
- **D-09 (Section height):** Full `100vh`, matching every other homepage section (Hero, Group 1/2/3, Footer) — keeps the scroll-snap rhythm. NOT letterboxed/shorter like the reference image's wide aspect ratio.
- **D-10 (Desktop column split):** 3 equal-width columns, each exactly `33.333vw` × `100vh`, no gaps implied by the reference (verify against reference image whether thin gaps/dividers exist — default to no gap, full-bleed edge-to-edge, since that matches the reference's seamless triptych look).
- **D-11 (Tagline placement — VARIES per panel, matching reference exactly):** This overrides the user's initial "same placement" wording after a clarifying round — the user confirmed they want the reference image's actual layout, which varies:
  - Panel 1 ("THE RACE."): top-left
  - Panel 2 ("THE MOMENT."): horizontally and vertically centered
  - Panel 3 ("YOURS."): bottom-right
- **D-12 (Mobile, <768px):** Stack vertically, full-width, matching the established mobile pattern used by every other section on this homepage (Hero, Manifesto, About Us all collapse to single-column stacking below 768px). Each panel becomes a shorter-than-100vh section on mobile (e.g. ~50-60vh each) to avoid an excessively tall 300vh scroll for 3 stacked full-height panels — exact mobile height is Claude's discretion (see below).

### Replacement Scope & Interactivity
- **D-13 (Full replacement):** The 3-panel reveal becomes the ENTIRE Manifesto section. Remove: the quote text ("and life has always been a race."), the corner-bracket frame decoration, the divider line, the `// MANIFESTO` label, and the stat tagline (ZERO COMPROMISE · ONE PURSUIT · INFINITE PRECISION) added in the previous session. None of that content carries forward into this redesign.
- **D-14 (No interactivity):** Panels are purely decorative/editorial — no click-through links, no hover states beyond whatever subtlety the reveal animation already provides. Do not wire `<a href>` wrappers around panels.
- **D-15 (Video background cutoff):** The homepage currently renders a fixed `<VideoBackground>` behind both Hero AND Manifesto, gated by `scrollTop < (vh * 2.3)` in `HomepageScrollytelling.tsx`. Reduce this threshold so the video stops rendering once Manifesto's panels come into view — Manifesto's own 3 images become its only visual background, no video bleed-through. Likely threshold: `vh * 1` (covers Hero only) — exact value is Claude's discretion, verify visually that the video fully clears before Manifesto's snap point.

### Claude's Discretion
- Exact mobile per-panel height (target ~50-60vh, adjust to avoid excessive total scroll length).
- Exact gap/no-gap between the 3 desktop columns (default: no gap, full-bleed, verify against reference).
- Exact stagger delay value within the 120-150ms range.
- Exact scale-from value within ~85-92% range for the "scale up from center" reveal.
- Whether a subtle dark overlay is needed under the taglines for legibility against bright image areas (the reference's images are high-contrast B&W, Pitwall's images may need slightly more wash for the difference-blend text to read clearly).

</decisions>
