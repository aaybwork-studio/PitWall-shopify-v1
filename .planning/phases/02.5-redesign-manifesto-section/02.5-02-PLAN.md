## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shopify CDN image URL -> `<img src>` | Image URLs originate from Shopify's own `image_url` filter (Plan 01), not from user/visitor input; rendered as a standard `<img>` src, no `dangerouslySetInnerHTML` or URL string concatenation into executable contexts |
| Merchant-authored tagline text -> DOM `<span>` | Tagline strings pass through Liquid's `escape` filter at the Liquid layer (Plan 01) before ever reaching React; React's JSX text-node rendering additionally auto-escapes any residual markup, so no HTML/script injection surface exists even if `escape` were bypassed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02.5-04 | Information Disclosure / Tampering | `<img src={manifestoImage1/2/3}>` | accept | Source is a Shopify-resolved CDN URL (string), never raw user input; React renders it as a plain attribute value, not interpreted as markup or script |
| T-02.5-05 | Tampering (XSS) | `<span>{manifestoTagline1/2/3}</span>` | accept | React JSX text children are auto-escaped by React's rendering; combined with the Liquid `escape` filter applied upstream (Plan 01), this is double-mitigated — no `dangerouslySetInnerHTML` is used anywhere in this task |
| T-02.5-06 | Denial of Service (layout/perf) | 3 large full-bleed images rendered simultaneously per viewport (desktop) or 3 stacked (mobile) | mitigate | `loading="lazy"` applied to all 6 `<img>` tags (3 desktop, 3 mobile) per the action spec, consistent with the existing lazy-load convention used elsewhere in this file (e.g. featured product images) |
