<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shopify schema → Liquid template | Shopify validates schema types; url type restricts to valid URLs |
| Liquid template → HTML attribute | Pipe escape filter prevents XSS in data-* attribute values |
| HTML attribute → JavaScript getAttribute | Returns decoded string — no double-decode issue with Liquid escape |
| JSON script textContent → JSON.parse | Liquid json filter produces valid JSON; parse errors caught by try/catch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.3-04-01 | XSS | founding_story in data-* attribute | mitigate | Use JSON script tag instead (RESEARCH.md recommendation) — avoids multi-sentence attribute escaping edge cases entirely |
| T-02.3-04-02 | XSS | about_heading in data-about-heading attribute | mitigate | Shopify schema type="text" + Liquid pipe escape filter applied; getAttribute() returns unescaped safe string; React renders as text node not innerHTML |
| T-02.3-04-03 | Injection | cta_url rendered as href in React | mitigate | Shopify schema type="url" restricts to valid URL formats; React blocks javascript: protocol hrefs since React 16; no eval or innerHTML involved |
| T-02.3-04-04 | Tampering | about-content-data script tag readable by all JS on page | accept | Content is non-sensitive marketing copy; same pattern as collection-products-data already in production; script type="application/json" is not executed by browser |
| T-02.3-04-05 | Denial of Service | JSON.parse failure on malformed about-content-data | mitigate | try/catch with Logger.error and hardcoded fallback strings — component renders with defaults even if script is malformed |
</threat_model>
